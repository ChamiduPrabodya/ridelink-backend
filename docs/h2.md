# H2 database setup

All four application services use Spring Data JPA with H2.
Start each service from its own directory so its database
files remain under that service's `data` folder.

| Service | JDBC URL |
| --- | --- |
| driver-vehicle-service | `jdbc:h2:file:./data/driverdb` |
| account-service | `jdbc:h2:file:./data/accountdb` |
| ride-service | `jdbc:h2:file:./data/ridedb` |
| fare-payment-service | `jdbc:h2:file:./data/paymentdb` |

Credentials: username `sa`, blank password. Hibernate updates the schema on startup.
Data persists across restarts. Local database files and migration snapshots are
excluded from Git.

## Driver and vehicle service

From `driver-vehicle-service`, run:

```powershell
.\mvnw.cmd spring-boot:run
```

- Drivers: `http://localhost:8082/api/drivers`
- Vehicles: `http://localhost:8082/api/vehicles`
- H2 console: `http://localhost:8082/h2-console`

In the H2 console, use driver class `org.h2.Driver`, JDBC URL
`jdbc:h2:file:./data/driverdb`, username `sa`, and a blank password.

IDs are numbers (`id`, `accountId`, `driverId`). For example:

```json
{
  "accountId": 3,
  "serviceArea": "Colombo",
  "latitude": 6.9271,
  "longitude": 79.8612,
  "availabilityStatus": "AVAILABLE"
}
```

## Data preserved when returning from MongoDB

All 2 drivers and 1 vehicle present at the switch were preserved and verified.
The original driver and vehicle retain ID `1`. The additional MongoDB driver
`6ab0ae95c2c735a5ffad5986` is now H2 driver ID `2` (account ID `2`).

`driver-vehicle-service/data/mongodb-to-h2-id-mapping.json` records the mapping.
The same directory contains a timestamped MongoDB JSON snapshot and a copy of the
H2 file from before the return migration. The MongoDB records remain available
as a backup; the application now writes to H2.

Run tests with `.\mvnw.cmd test`. Driver/vehicle persistence tests use a separate
in-memory H2 database and do not modify saved application records.
